Upload a registry CSV or dependency-inventory JSON

Registry CSV (fetches each branch's SBOM). The first line must be exactly header. One row per repository branch; provider is one of github. Listed rows are added or updated; repositories not in the file are left untouched (nothing is deleted). Every row and every SBOM is checked before anything is saved; if one fails, the whole file is rejected.

SBOMs (CycloneDX JSON or SPDX 2.x JSON) are fetched over HTTPS from allowlisted hosts only: none configured yet (set eol.sbom.hosts) host. Tokens come from server configuration, never from the CSV.

Dependency-inventory JSON (a .json file, nothing is fetched): a root array with one object per repository branch: required name, url and branch (no default branch is assumed); optional appId, provider, sbom (url may be null, generatedAt), projects (path, ecosystem, packageManager, resolution); and a required dependencies array ([] for none) with one row per resolved graph edge: name, version, optional purl (its version must equal version), scope, dependencyType, depth, parentCoordinate, projectPath and more. Every row is kept with its snapshot; each distinct package + version is listed once for EoL matching. A branch gets a new snapshot when anything except sbom.generatedAt changed. URLs and evidence paths in the file are recorded as provenance and never fetched; refreshes skip these branches, so re-upload the JSON to update them. See the format example (hand-written, not resolver output).
